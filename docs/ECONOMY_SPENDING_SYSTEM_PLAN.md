# 월덕 가상경제 소비 시스템 기획서

- 문서 버전: 1.0
- 작성일: 2026-08-21
- 대상 프로젝트: 월덕 가상 경제 웹사이트·Discord 봇
- 문서 상태: 개발 검토용
- 범위: 게임 내 가상화폐 소비 시스템, 경제 원장 정상화, 운영 지표, QA 및 출시 계획

## 1. 요약

현재 프로젝트에는 출석, 일하기, 자동 채굴, 사업, 은행, 주식, 카지노, 로또 등 재화를 생성하거나 재분배하는 기능이 많다. 반면 사용자가 자발적으로 반복 구매할 만한 소비처는 일부 기간제 오라, 영구 칭호, 버프 아이템, 드릴 강화에 집중되어 있다.

이번 기획의 핵심은 세금을 강제로 높이거나 도박을 더 추가하는 것이 아니라 다음의 반복 소비 루프를 만드는 것이다.

> 재화 획득 → 저가 꾸미기 구매 → 중복 아이템 수집·제작 → 프로필과 덕하우스 전시 → 시즌·커뮤니티 명예 경쟁

1차 출시 범위는 다음 세 가지다.

1. **주간 명예 상점**: 저가부터 고가까지 접근 가능한 기간제·영구 외형 판매
2. **컬렉션 제작소**: 중복 아이템과 제작비를 함께 소모하는 확정 제작
3. **덕하우스**: 구매한 장식과 업적을 전시하는 개인 공간

경매장, 공동 프로젝트, 시즌 명예 패스는 활성 유저가 충분히 늘어난 뒤 단계적으로 도입한다.

## 2. 목표와 비목표

### 2.1 목표

- 신규 유저가 가입 후 1~3일 안에 첫 소비를 경험하게 한다.
- 일반 유저에게는 매일·매주 살 것이 있고, 고액 보유자에게는 장기 목표가 있게 한다.
- 구매 결과를 웹 프로필, 랭킹, 채팅, 사업장 등 공개 영역에서 확인할 수 있게 한다.
- 현금 보상보다 외형, 수집, 명예, 편의 중심으로 소비 가치를 제공한다.
- 재화 생성·소각·국고 이동·유저 간 이동을 정확히 분리하여 측정한다.
- 웹과 Discord가 동일한 서비스 계층과 트랜잭션을 사용하게 한다.

### 2.2 비목표

- 실제 현금 결제 또는 현금성 환전 기능은 포함하지 않는다.
- 확률형 상품과 카지노를 주 소비처로 만들지 않는다.
- 기존 유저가 이미 구매한 권리를 회수하거나 강제로 유지비를 부과하지 않는다.
- 유저 자산에 따라 동일 상품 가격을 다르게 받지 않는다.
- 소비 아이템으로 무제한 재화를 생산하는 Pay-to-Win 구조를 만들지 않는다.

## 3. 현재 상태 분석

### 3.1 기존 재화 유입원

- 초기 정착금 10,000원
- 출석 보상과 연속 출석 보너스
- 10분 쿨타임 일하기
- 저소득 유저 지원금
- 수동·자동 채굴
- 사업 수금
- 은행 이자
- 주식 배당 및 매매 차익
- 카지노·로또 당첨금
- 관리자 지급 및 국고 환급

### 3.2 기존 소비·유출처

- 기간제 오라 100,000~500,000원
- 영구 칭호 200,000원
- 버프·보험·힌트·수수료 면제 아이템 10,000~50,000원
- 럭키박스 5,000원
- 확성기 50,000원
- 드릴 강화 5,000~10,000,000원
- 사업 구매·강화·직원·본사 확장
- 로또 구매액 중 30% 소각
- 주식 거래세, 송금 수수료, 재산세

### 3.3 핵심 문제

1. **가격 사다리가 비어 있다.** 일반 유저 자산 중앙값에 비해 오라와 칭호가 비싸고, 2,000~20,000원대에서 자주 살 만한 외형 상품이 부족하다.
2. **반복 소비가 약하다.** 영구 칭호는 한 번 구매하면 끝나며, 보유 아이템을 다시 소비하거나 진화시키는 구조가 없다.
3. **경제 원장이 실제 흐름을 정확히 반영하지 못한다.** 주식 원금 이동, 유저 송금, 국고 이동, 진짜 소각이 한데 섞여 있다.
4. **자동 채굴 지급이 설계보다 크다.** 최근 활동 조건과 6시간 상한이 실제 지급 쿼리에 적용되지 않는다.
5. **광업 기업 실적 연동이 과도하다.** 코드상 채굴액의 10%가 아니라 10배가 적립되고, 반복 기본금 가산 가능성이 있다.
6. **사업 유지비는 실제 소각이 아니다.** 지급 예정액에서 제외될 뿐 유저가 가진 통화를 제거하는 행위가 아니다.
7. **로또 원장이 티켓값 전액을 소각으로 기록한다.** 실제 소각은 30%이고 나머지 70%는 잭팟 준비금이다.
8. **럭키박스가 일반 상품을 잠식한다.** 5,000원 상자에서 표시 가격 기준 기대가치가 약 27,500원인 아이템이 나오므로 직접 구매 매력이 떨어진다.
9. **현재 시뮬레이션이 운영 코드를 재사용하지 않는다.** 실제 채굴·국고·사업 로직의 오류를 잡지 못한다.

## 4. 설계 원칙

### 4.1 재미있는 소비를 우선한다

강제 세금은 경제 조절 장치일 수는 있지만 사용자가 돈을 벌고 싶게 만드는 콘텐츠는 아니다. 주 소비처는 다음 세 가치를 제공해야 한다.

- **표현**: 프로필, 채팅, 랭킹, 사업장, 덕하우스 외형
- **수집**: 세트 완성, 도감, 희귀도, 시즌 기록
- **명예**: 후원자 배지, 전용 이름표, 전시 슬롯, 명예의 전당

### 4.2 가격은 여러 상품 등급으로 제공한다

동일 상품을 자산에 따라 차등 가격으로 판매하지 않는다. 대신 상품군을 다음처럼 나눈다.

| 등급 | 목적 | 초기 제안 가격 | 목표 구매 주기 |
|---|---|---:|---|
| 체험 | 첫 소비와 즉시 만족 | 2,000~5,000원 | 1~3일 |
| 일반 | 주간 꾸미기·수집 | 10,000~50,000원 | 1주 |
| 명예 | 월간 외형·컬렉션 | 100,000~500,000원 | 2~6주 |
| 전설 | 고액 보유자 장기 목표 | 1,000,000원 이상 | 1~3개월 |

가격은 경제 정상화 후 일반 유저의 7일 획득액 중앙값을 기준으로 다시 산정한다.

- 체험 상품: 7일 획득액의 5~10%
- 일반 상품: 7일 획득액의 40~80%
- 명예 상품: 3~8주 획득액
- 전설 상품: 고정가 또는 공개 경쟁 방식

### 4.3 구매 상품의 기대 재화 수익은 가격보다 낮아야 한다

- 순수 외형 상품의 재화 반환은 0원으로 한다.
- 편의·버프 상품이 추가로 만들어내는 기대 재화는 구매가의 70% 이하를 목표로 한다.
- 재화 보상을 주는 상자나 제작법은 핵심 소비처에서 제외한다.
- 확률형 상품을 유지한다면 확률 공개, 중복 처리, 천장 규칙을 반드시 제공한다.

## 5. 선행 작업: 경제 정상화

신규 상점을 출시하기 전 다음 항목을 P0으로 처리한다.

### 5.1 자동 채굴

- 최근 활동 시점 기준 6시간까지만 자동 채굴을 허용한다.
- 서버가 꺼져 있던 시간을 한 번에 무제한 소급 지급하지 않는다.
- 초당 정수 지급 대신 누적 소수점 또는 분 단위 지급으로 변경한다.
- 자동 채굴 레벨 1의 투자 회수 기간을 최소 5~7일로 조정한다.
- 자동 조절 설정 이름을 `clickerYieldMultiplier` 또는 공통 `miningYieldMultiplier`로 통일한다.
- 웹, Discord, 백그라운드 지급에 같은 계산 함수를 사용한다.

### 5.2 광업 기업 실적

- `채굴 지급액 × 10`을 `채굴 지급액 × 0.10`으로 수정한다.
- 기존 행 갱신 때 기본금 10,000,000원이 반복 가산되지 않게 한다.
- 배당 지급과 기업 실적 적립을 별도 원장 이벤트로 기록한다.

### 5.3 통합 경제 원장

원장 이벤트를 다음 의미로 분리한다.

| 이벤트 | 의미 | 유저 M2 변화 | 진짜 소각 여부 |
|---|---|---:|---|
| `MINT` | 시스템 신규 발행 | 증가 | 아니요 |
| `BURN` | 시스템에서 영구 제거 | 감소 | 예 |
| `TREASURY_IN` | 유저에서 국고로 이동 | 감소 | 아니요 |
| `TREASURY_OUT` | 국고에서 유저로 이동 | 증가 | 아니요 |
| `RESERVE_IN` | 유저에서 카지노·잭팟 준비금으로 이동 | 감소 | 아니요 |
| `RESERVE_OUT` | 준비금에서 유저로 이동 | 증가 | 아니요 |
| `TRANSFER` | 유저 간 이동 | 변화 없음 | 아니요 |
| `ASSET_CONVERT` | 현금과 주식·사업 등 자산 간 전환 | 현금만 변화 | 아니요 |

필수 원장 필드:

- `flow_type`, `category`, `amount`
- `user_id`, `target_user_id`
- `balance_before`, `balance_after`
- `environment` (`test`, `production`)
- `actor_kind` (`USER`, `ADMIN`, `SYSTEM`, `TEST`)
- `idempotency_key`
- `metadata`, `created_at`

관리자·테스트 계정은 기록하되 일반 경제 대시보드 집계에서는 제외한다.

### 5.4 기존 기능 보정

- 로또 구매는 `BURN 30%`와 `RESERVE_IN 70%`로 나눠 기록한다.
- 로또 당첨금은 `RESERVE_OUT`으로 기록한다.
- 사업 유지비는 `PREVENTED_MINT` 지표로 기록하거나 실제 국고 이동으로 변경한다. 두 방식을 동시에 적용하지 않는다.
- 럭키박스 구매와 개봉을 하나의 DB 트랜잭션으로 묶는다.
- 개봉한 럭키박스 재고를 정확히 차감한다.
- 출석 명령의 사용자 이름 참조 오류를 수정한다.
- 경제 시뮬레이션은 운영 계산 함수를 직접 호출하도록 변경한다.

## 6. 기능 1: 주간 명예 상점

### 6.1 목적

모든 자산 구간의 사용자가 자발적으로 자주 소비할 수 있는 외형 중심 상점이다. 기존 명품 상점 안에 `주간 명예 상점` 탭을 추가한다.

### 6.2 상품 구성 예시

| 상품 | 기간 | 가격 | 노출 위치 |
|---|---:|---:|---|
| 프로필 포인트 색상 | 7일 | 3,000원 | 프로필·랭킹 |
| 닉네임 색상 | 7일 | 5,000원 | 프로필·랭킹 |
| 정적 프로필 테두리 | 30일 | 20,000원 | 프로필·랭킹 |
| 사업장 간판 스킨 | 30일 | 30,000원 | 사업 페이지 |
| 확성기 특수 테마 | 1회 | 10,000원 추가 | 홈·Discord |
| 애니메이션 프로필 테두리 | 30일 | 100,000원 | 프로필·랭킹 |
| 덕하우스 외관 스킨 | 영구 | 500,000원 | 덕하우스 |
| 전설 후원자 명판 | 시즌 | 1,000,000원 | 홈·명예의 전당 |

### 6.3 로테이션

- 매주 일요일 00:00 KST에 상품 6~8종을 교체한다.
- 최소 2종은 5,000원 이하로 유지한다.
- 최소 1종은 고액 보유자용 상품으로 유지한다.
- 판매 시작·종료 시각은 DB에 UTC로 저장하고 화면에서 KST로 표시한다.
- 관리자는 다음 주 상품을 미리 등록·미리보기할 수 있다.
- 같은 상품은 모든 유저에게 같은 가격으로 노출한다.

### 6.4 웹 화면

- 상품 카드: 미리보기, 가격, 남은 시간, 보유 여부, 적용 기간
- 구매 버튼: 잔액 부족 시 필요한 추가 금액 표시
- `보유 중`, `장착 중`, `만료 예정` 상태를 구분
- 구매 후 잔액과 인벤토리를 실시간 갱신
- 프로필에서 장착·해제 가능

### 6.5 Discord 명령어

- `/명예상점 목록`
- `/명예상점 구매 상품`
- `/꾸미기 보유`
- `/꾸미기 장착 아이템`
- `/꾸미기 해제 부위`

명령어와 웹 API는 동일한 `prestigeShopService`를 호출한다.

### 6.6 구매 처리 규칙

1. 서버가 로그인 사용자를 확인한다.
2. 클라이언트가 보낸 가격은 사용하지 않고 DB의 현재 가격을 다시 조회한다.
3. 상품 판매 기간, 구매 제한, 기존 보유 상태를 확인한다.
4. 사용자 행을 `FOR UPDATE`로 잠근다.
5. 잔액 차감, 인벤토리 지급, 경제 원장 기록을 한 트랜잭션으로 처리한다.
6. 성공 후 웹·Discord 실시간 동기화 이벤트를 전송한다.
7. 동일 `idempotency_key` 요청은 한 번만 처리한다.

## 7. 기능 2: 컬렉션 제작소

### 7.1 목적

중복 소비 아이템이 쌓이는 문제를 해결하고, 아이템과 현금을 동시에 제거하는 반복 소비처를 만든다. 결과는 무작위가 아니라 사용자가 선택한 확정 보상으로 제공한다.

### 7.2 기본 흐름

1. 사용자가 중복 소비 아이템을 분해한다.
2. 아이템 종류와 희귀도에 따라 양도 불가능한 `황금 깃털 조각`을 받는다.
3. 조각과 제작비를 함께 사용해 배지, 테두리, 장식을 확정 제작한다.
4. 제작 결과를 프로필 또는 덕하우스에 전시한다.

`황금 깃털 조각`은 현금과 거래할 수 없는 제작 재료이며, 새로운 거래 화폐로 사용하지 않는다.

### 7.3 분해 기준 초안

| 분해 대상 | 획득 조각 |
|---|---:|
| 일반 소비 아이템 1개 | 1개 |
| 고급 소비 아이템 1개 | 3개 |

활성화 중인 기간제 아이템과 보호권은 기본 선택 대상에서 제외하여 실수 분해를 방지한다.

### 7.5 안전 규칙

- 분해 전 예상 조각과 사라지는 아이템을 확인창에 표시한다.
- 영구 외형 분해는 아이템명을 다시 입력하거나 2단계 확인을 요구한다.
- 분해·제작은 되돌릴 수 없다는 문구를 명확히 표시한다.
- 모든 분해·제작 내역을 감사 로그로 남긴다.
- 제작비는 `BURN/CRAFT_FEE`, 아이템 제거는 `ITEM_SINK`로 기록한다.

## 8. 기능 3: 덕하우스

### 8.1 목적

구매한 상품과 업적을 실제로 보여줄 개인 공간을 제공한다. 기존 사업 본사 레벨과 충돌하지 않도록 별도 `덕하우스` 시스템으로 구성한다.

### 8.2 기본 구성

- 모든 유저에게 기본 방 1개와 기본 테마 제공
- 배경, 바닥, 가구, 벽 장식, 동상, 명판 슬롯 제공
- 웹 프로필에서 다른 유저의 덕하우스 방문 가능
- 보유 아이템을 배치하고 미리보기 가능
- 좋아요·방명록은 악용 방지와 운영 인력이 준비된 뒤 추가

### 8.3 확장 가격 초안

| 단계 | 전시 슬롯 | 가격 |
|---|---:|---:|
| 기본 방 | 3개 | 무료 |
| Lv.2 응접실 | 5개 | 50,000원 |
| Lv.3 갤러리 | 8개 | 250,000원 |
| Lv.4 펜트하우스 | 12개 | 1,000,000원 |
| Lv.5 월덕 궁전 | 18개 | 5,000,000원 |

확장은 영구 소유한다. 기존 소유권을 잃게 하는 강제 유지비는 부과하지 않는다. 대신 특별 조명, 날씨, 파티 효과 등 선택형 기간제 효과를 판매한다.

### 8.4 전시 가치

- 프로필에 `덕하우스 방문` 버튼 제공
- 랭킹 상위권과 시즌 후원자의 집에 특별 배지 표시
- 컬렉션 완성 세트를 배치하면 전용 시각 효과 제공
- 시각 효과는 채굴·사업·주식 수익률에 영향을 주지 않는다.

## 14. 보안·악용 방지

- 가격, 사용자 ID, 지급 아이템을 클라이언트 입력값으로 신뢰하지 않는다.
- 모든 구매·분해·제작·기부는 DB 트랜잭션으로 처리한다.
- 잔액 행을 잠그고 음수 잔액을 DB와 서비스 양쪽에서 방지한다.
- 웹과 Discord의 중복 요청 방지를 위해 idempotency key를 사용한다.
- 구매·제작 API에 사용자별 속도 제한을 적용한다.
- CSRF 방어, SameSite 쿠키, Origin 검증을 적용한다.
- 상품명, 메시지, 명판 문구는 HTML 이스케이프 및 길이 제한을 적용한다.
- 관리자·테스트 계정 활동은 별도 태그와 감사 로그로 기록한다.
- 만료 작업은 재실행해도 같은 결과가 되는 idempotent 배치로 만든다.
- 금액은 JavaScript `Number`가 아니라 `BigInt`와 DB `DECIMAL(65,0)`을 사용한다.

## 15. 운영 지표

### 15.1 필수 경제 지표

- 일반 유저 1일·7일 `MINT`
- 일반 유저 1일·7일 `BURN`
- 국고 유입과 재지급
- 카지노·로또 준비금 유입과 지급
- 현금+예금 M2
- 자산 중앙값, P90, P99
- 신규 유저의 첫 구매까지 걸린 시간
- 상품별 노출·구매 전환율
- 구매 유저의 7일·30일 재구매율
- 가격 구간별 매출과 구매자 수
- 사용되지 않는 인벤토리 수량

### 15.2 초기 목표값

표본이 작으므로 절대 기준으로 자동 제재하지 않고 경고 지표로 사용한다.

- 신규 유저 첫 구매 중앙값: 가입 후 72시간 이내
- 주간 활성 유저의 상점 구매 참여율: 25% 이상
- 구매 유저 30일 재구매율: 30% 이상
- 성장기 7일 실제 소각/신규 발행 비율: 50~70%
- 안정기 7일 실제 소각/신규 발행 비율: 70~90%
- 일반 유저 자산 중앙값은 성장하되 P90과의 격차가 매주 급격히 벌어지지 않을 것

목표를 벗어나면 세금을 즉시 높이기보다 상품 가격, 로테이션, 소비 가치, 재화 생성량을 순서대로 조정한다.

### 16.1 기능 QA

- 비로그인 사용자는 구매·제작·기부 불가

- 다른 사용자 ID로 구매 시도
- CSRF와 반복 요청

## 19. 완료 조건

### 19.1 주간 명예 상점

- 관리자가 코드를 수정하지 않고 상품과 판매 기간을 등록할 수 있다.
- 유저가 웹과 Discord에서 같은 상품과 잔액을 본다.
- 구매 실패 시 돈이나 아이템이 일부만 변경되지 않는다.
- 구매한 외형을 프로필 또는 덕하우스에 장착할 수 있다.

### 19.2 컬렉션 제작소

- 중복 아이템을 안전하게 분해할 수 있다.
- 제작 재료와 현금이 정확히 차감된다.
- 결과 아이템이 한 번만 지급된다.
- 분해와 제작 내역을 관리자가 추적할 수 있다.

### 19.3 덕하우스

- 모든 유저가 기본 공간을 가진다.
- 레벨에 따라 전시 슬롯이 정확히 제한된다.
- 다른 유저가 공개 덕하우스를 볼 수 있다.
- 덕하우스 아이템은 재화 수익률을 올리지 않는다.

- 첫 개발 묶음은 `경제 정상화 + 주간 명예 상점 + 컬렉션 제작소`로 한다.
- 기존 명품 상점은 제거하지 않고 새 가격 사다리와 장착 화면을 추가한다.
- 럭키박스는 금융 버프 중심 보상에서 확률이 공개된 외형 중심 보상으로 개편한다.
- 덕하우스는 기존 사업 본사와 분리한다.
- 두 번째 거래 가능 화폐는 만들지 않는다. 제작 재료는 계정 귀속으로만 사용한다.
- 경매장은 주간 활성 일반 유저 30명 전에는 개발 우선순위에서 제외한다.
- 세율과 상점 가격 자동 변경은 7일 이상 정상 원장을 확보한 뒤 적용한다.
