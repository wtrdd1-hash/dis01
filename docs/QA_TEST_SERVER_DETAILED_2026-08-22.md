# 테스트 서버 정밀 QA 리포트

- 대상: https://test.easy-scraping.com/
- 일시: 2026-08-22 KST
- 범위: 공개 웹 UI, 주식 시세 화면, 접근 권한, 금액/원장 로직 회귀 테스트, 관리자 경제 QA 이력 대조
- 판정: **조건부 실패 (관리자 경제 제어 P1 잔존 여부를 배포본에서 재검증해야 함)**

## 핵심 결론

공개 화면 6개(주식·상점·카지노·채굴·랭킹·VIP 광장)는 모두 렌더링됐고, 이번 점검 중 브라우저 콘솔 오류는 없었다. 주식 화면의 섹터 필터, 카드/테이블 전환, 상세 차트 모달도 정상 동작했다. **단, 로그인 후 실제 채굴 보상은 테스트 서버에서 지급되지 않아 채굴 핵심 기능은 실패다.**

다만, 같은 날짜의 인증 관리자 전용 QA에서 경제 정책 제어가 **성공으로 표시되지만 런타임 경제 엔진에 즉시 적용되지 않는 P1** 등 15개 실패가 확인됐다. 현재 작업 트리에는 이를 고치는 변경이 있으나 아직 커밋/배포 검증되지 않은 상태다. 따라서 테스트 서버에서 해당 수정이 반영됐다고 결론 내릴 수 없다.

## 주식 가격 점검

관측 시점 시장 상태는 `월덕 경제 번영기 (Duck Prosperity)`였다. 10개 종목이 렌더링됐고, 현재 틱 기준으로 AICH +3.38%, BANK +3.66%, BIOX +3.66%, CHKN +3.79%, DUCK +3.96%, NEKO +4.13%, SCRP +3.84%, SLOT 0.00%, SPAC +3.93%, WTRD +3.84%였다.

- 가격은 0원/음수/NaN으로 표시되지 않았고 차트 상세의 현재가·이전가·24시간 고저값도 표시됐다.
- 이번 한 번의 스냅샷에서는 9개 종목이 상승, 1개 종목이 보합이다. 상승 국면에서는 가능하지만, 하락 국면·여러 틱에 대한 분포 검증은 인증 DB/관리자 로그 없이는 완료할 수 없다.
- 코드상 종목별 독립 노이즈와 개별 충격을 적용하도록 되어 있어 ‘모든 종목이 동일 비율로 움직이는’ 이전 문제에 대한 방어 로직은 존재한다. 실제 서버에서 여러 주기 동안의 로그 분포 재검증이 필요하다.

## 돈이 늘고/줄어드는지

### 확인된 정상 동작

인증 관리자 전용 경제 QA(`docs/QA_ADMIN_ECONOMY_2026-08-22.md`)에서 임시 사용자를 사용해 다음을 확인했고, 테스트 데이터는 삭제·복원됐다.

| 동작 | 전 잔액 | 요청 | 후 잔액 | 결과 |
|---|---:|---|---:|---|
| 관리자 지급 | 100,000원 | +777원 | 100,777원 | PASS |
| 관리자 회수 | 100,777원 | -333원 | 100,444원 | PASS |
| `confirm=true` 없는 회수 | 100,444원 | -1원 | 변동 없음 | PASS, 서버가 400으로 차단 |
| 0원/문자열/없는 사용자 | - | 잘못된 지급·회수 | 변동 없음 | PASS, 거부 |

상점 구매와 로또 구매도 단위 테스트에서 잔액, 아이템/티켓, 경제 원장이 하나의 트랜잭션으로 함께 반영되거나 함께 롤백되는 것을 확인했다. 이번 브라우저 QA에서는 관리자 테스트 계정에만 5,000,000원을 일시 지급해 SLOT 1주 매수·매도와 플링코 1회 결과를 실제로 확인했으며, 종료 시 잔액을 다시 0원으로 복구했다.

### 주의할 동작

- 관리자 회수는 의도적으로 음수 현금(채무)을 허용한다. 기능 자체는 정책일 수 있으나, 관리자 UI에는 잔액 초과 회수와 음수 전환에 대한 2차 확인/명확한 경고가 필요하다.
- 비로그인 화면의 잔액 0원은 세션이 없기 때문이다. 로그인한 관리자 테스트 계정의 지급·매수·매도·게임 후 잔액 증감은 확인했지만, 채굴은 P1 결함으로 지급 자체가 되지 않았다.

## 발견 사항 및 우선순위

### P1 — 로그인 사용자의 채굴이 전부 차단됨

테스트 서버에서 Discord 관리자 계정으로 로그인한 뒤 채굴 화면을 직접 조작했다. 최초 상태는 현금 0원, 드릴 Lv.1, 총 채굴 0회, 최근 획득 0원이었다. 채굴 버튼을 누르고 2초 이상 간격을 둔 뒤 다시 눌러도 모든 값이 그대로였으며, 화면에는 `⚠️ 연타 제한: 0.1초 후 클릭`만 표시됐다.

원인 확인:

- 화면은 `/api/clicker/click`에 `hits`, `clicks`만 보내고 채굴 창 식별자 `wid`를 보내지 않는다. (`src/web/views/mining.ejs`)
- 서버는 `wid`가 없으면 `claimMinerSlot()`에서 `invalid`으로 차단한다. (`src/web/routes/economyRoutes.js`, `src/utils/clickGuard.js`)
- 프런트엔드는 `blocked`의 원인을 구분하지 않고 전부 연타 제한으로 표시한다. 따라서 유저는 기다리면 해결되는 문제로 오인한다.

영향: 로그인한 모든 사용자가 정상 클릭으로 현금을 얻지 못하며, 채굴 횟수·크리티컬·드릴 보너스·자동채굴 경제 루프를 시작할 수 없다.

권고:

1. 페이지 초기화 시 8~64자 형식의 안정적인 `wid`를 생성해 모든 `/api/clicker/click` 요청에 포함한다.
2. `invalid`는 `채굴 세션을 초기화하지 못했습니다. 페이지를 새로고침해 주세요.`처럼 별도 표시한다.
3. 채굴 첫 클릭 후 `earnedCash > 0`, `newCash` 증가, `totalClicks` 증가를 확인하는 브라우저 통합 테스트를 배포 차단 조건에 추가한다.

### P2 — 주식·카지노의 성공 알림이 브라우저 기본 alert임

실제 SLOT 매수/매도와 플링코 베팅은 잔액과 보유 수량에 정상 반영됐다. 그러나 결과를 브라우저 기본 alert로 표시해 화면 흐름이 중단된다. 테스트 자동화와 사용자 경험 모두에서 불리하며, 다크 UI의 토스트 체계와도 일관되지 않는다.

권고: 결과·실패·잔액 변동을 비차단 토스트와 주문/베팅 내역 패널로 표시한다.

### P2 — 관리자 공지 메뉴가 공지 화면이 아닌 명령 콘솔로 연결됨

관리자 사이드바의 `📢 공지-팝업 등록` 링크(`/admin/announcements`)를 직접 열었을 때 제목과 본문이 `명령 및 조작 - 관리자`의 경제 조작 콘솔로 표시됐다. 공지 등록 화면에 독립적으로 진입할 수 없다.

권고: `/admin/announcements` 라우트와 템플릿을 분리하거나, 의도적으로 콘솔 내 공지 탭을 쓸 경우 메뉴명·URL·초기 선택 탭을 일치시킨다.

### P1 — 관리자 경제 정책이 실제 엔진과 불일치할 수 있음 (배포본 재검증 필수)

오늘의 인증 관리자 QA에서 세율, 부유세 배율, 예금금리, 지원금 배율, 자산세 기준이 API/DB에는 저장되지만 실행 중 엔진의 snapshot에 즉시 반영되지 않는 현상이 확인됐다. 이 경우 관리자는 ‘적용됨’으로 오인하고 실제 지급·세금·금리는 이전 정책으로 동작할 수 있다.

현재 로컬 변경에는 `updateDynamicSetting()`으로 런타임 상태를 직접 바꾸고 DB 실패 시 롤백하는 수정이 포함되어 있다. 그러나 변경이 미커밋 상태이므로 **테스트 서버 반영 및 재실행 전에는 해결로 판정하지 않는다.**

### P1 — 시장 국면 자동 복귀/유효범위, 금리/지원금/자산세 연동은 재검증 필요

기존 인증 QA에서는 자동 국면 요청이 0번 국면으로 바뀌고, 존재하지 않는 인덱스 9가 허용되는 문제가 있었다. 또한 관리자 금리·지원금 배율·자산세 기준의 실제 소비 경로 불일치가 발견됐다.

현재 로컬 변경에는 null 처리, 국면 0~8 범위 검증, 실제 주식 엔진 연결, 수동 금리 우선, 지원금 배율 적용, 자산세 기준/배율 범위 통일이 포함되어 있다. 배포된 테스트 서버에서 정책 변경 직후 snapshot과 실제 지급/세금 결과를 다시 비교해야 한다.

### 재확인 통과 — 랭킹 식별·주식 카드 접근성

이번 배포본의 랭킹은 동일 표시명 뒤에 짧은 `#` 식별자를 함께 표시했다. 또한 주식 카드 상세 진입은 `aria-label`이 있는 실제 버튼으로 렌더링됐다. 따라서 이전 QA에서 기록된 ‘동일 이름 구분 불가’와 ‘카드 키보드 접근성 부족’은 현재 배포본에서는 재현되지 않았으며, 열린 결함으로 집계하지 않는다.

### P2 — 배포 회귀 검증 누락 위험

인증 QA 당시 컨테이너의 `npm test`가 테스트 0건으로 성공했다. 현재 Dockerfile에는 `test` 복사 수정이 있으나 미커밋이다. 또한 이번 로컬 실행도 DB 의존 3건을 건너뛰었다.

권고: CI에서 최소 실행 테스트 수를 강제하고, 테스트 컨테이너에서 MySQL을 포함한 통합 테스트를 실패 조건으로 둔다.

### P3 — 관리자 금액 조작의 실수 방지 UX

서버는 `confirm=true`를 강제하지만 관리자 모달은 지급/회수를 한 번 누르면 즉시 확정한다. 회수는 음수 채무가 가능하므로 금액·대상·예상 후 잔액을 보여주는 2차 확인이 필요하다.

## 이미 확인된 보안/검증 항목

- 비관리자 관리자 페이지/API 접근 403
- 악성 Origin의 관리자 쓰기 요청 403
- 경제 로그 검색 SQL injection 형태 입력 안전 처리
- 검색값 HTML 이스케이프
- 잘못된 지급/회수 금액 및 없는 사용자 거부

## 재검증 순서

1. 현재 로컬 수정사항을 테스트 서버에 배포한다.
2. `scripts/qa_economy_page.js`를 테스트 컨테이너에서 실행한다. 이 도구는 임시 사용자와 변경 설정을 종료 시 복원한다.
3. 관리자 화면에서 세율·금리·지원금·자산세 기준·시장 국면을 하나씩 변경하고, API 응답/DB/snapshot/실제 지급 또는 세금 결과가 모두 같은지 확인한다.
4. 10개 종목 이상을 10~20틱 관찰해 음수 가격, 0원, NaN, 전 종목 동일 변동률, 1틱 ±15% 이상 급변, 24h 고저 역전 여부를 검사한다.
5. MySQL 포함 테스트 환경에서 전체 `npm test`를 실행하고, 실행 건수가 0이거나 skip된 핵심 통합 테스트가 있으면 배포를 차단한다.

## 제한 사항

초기 공개 화면 점검 시에는 Discord 관리자 로그인 세션이 없었다. 이 구간의 관리자 경제 제어 수치 결과는 같은 날짜에 정식 서명 관리자 세션으로 실행·정리된 전용 QA 기록을 근거로 했으며, 그 이후의 미배포 수정은 ‘해결’로 간주하지 않았다.

이후 동일 브라우저에서 Discord 관리자 계정으로 로그인해 실제 사이트 QA를 추가 수행했다. 테스트 계정에만 5,000,000원의 가상 자금을 임시 지급해 주식 매수·매도와 플링코 결과 반영을 확인했고, 사용 후 남은 4,999,800원은 같은 계정에서 전액 회수해 현금 0원으로 복구했다. 사이트에 영구 메시지를 보내는 광장 채팅/확성기, 다른 이용자 차단, 공지 생성·삭제, 전체 사용자 데이터 초기화, 국고/상장폐지처럼 다수 사용자 또는 서버 전체 상태를 바꾸는 파괴적 관리자 기능은 수행하지 않았다. 이 항목들은 전용 임시 사용자·명확한 복구 계획을 마련한 별도 실행에서만 검증해야 한다.
